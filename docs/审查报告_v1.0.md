# 生活工作台（LifeWorkbench.apk）产品审查报告

> 审查对象：`LifeWorkbench.apk`（58KB，包名 `com.lifewb.app`）
> 技术形态：Android WebView 壳 + 单文件 HTML 应用（`assets/index.html`，2220 行，8 个功能模块，localStorage 持久化）
> 审查日期：2026-08-05 · 审查维度：底层逻辑 / Bug / 大众审美 / 功能完整性 / 竞品对比

---

## 一、总体结论（先说重要的）

**这是一个工程素质明显高于平均水平、但存在一个"致命数据死局"的个人作品。**

优点：单文件应用里少见的完整设计系统（颜色/字号/间距/圆角 token 化）、统一的数据访问层、损坏数据隔离、纯 SVG 零依赖图表、演示数据与迁移机制、跑鞋寿命/热量缺口/PB 纪录等有真实洞察力的细节。

**但有三件事必须在发布前修掉，否则用户数据会丢：**

1. **「导出备份」在 APK 里完全无效** —— WebView 壳没有设置 `DownloadListener`，点击导出毫无反应。
2. **「导入恢复」在 APK 里完全无效** —— 壳没有实现 `WebChromeClient.onShowFileChooser`，点文件选择框弹不出来。
3. **健身「目标进度」对减重目标永远显示 0%** —— 公式符号写反了（详见 Bug-P0-3）。

前两条叠加意味着：**用户数据只能进、不能出，卸载/清数据 = 永久丢失且无法备份。** 对于一个以"记录"为核心价值的产品，这是生死问题。

### 评分总览（10 分制）

| 维度 | 得分 | 简评 |
|---|---|---|
| 底层架构与代码质量 | 7 | 模块化清晰，容错意识好；扣分在壳层能力缺失 |
| 数据安全与可靠性 | 3 | 导出/导入双坏 + localStorage 单点存储，零容灾 |
| 功能完整性 | 5 | 8 模块广度够，每个模块深度不足，全部"只能增删不能改" |
| 视觉与交互（大众审美） | 7 | 干净克制，但导航反人体工学、品牌色缺失、无深色模式 |
| 市场竞争力 | 4 | 目前是每个垂直领域的"简配版"，需找到差异化定位 |
| **综合** | **5.5** | 修完 P0/P1 可达 7.5+ |

## 二、底层逻辑审查

### 2.1 架构优点（值得保留）

- **分层合理**：`Store`（容错读写）→ `Data`（数据访问）→ 8 个模块（Today/Finance/Habits/Fitness/Run/Schedule/Shopping/Media）→ `UI/Charts` 组件层，职责清晰。
- **存储容错亮眼**：`Store.get` 解析失败时把损坏数据另存为 `corrupted_*` 备份再重置，并 toast 提示——很多商业 App 都没做这个。
- **配额兜底**：`QuotaExceededError` 有专门提示。
- **演示数据 + 版本迁移机制**（`demo_version`）有产品意识。
- **备份提醒**：数据 ≥20 条时横幅提醒导出——方向正确（但阈值有问题，见 Bug-P1-8）。

### 2.2 架构缺陷（底层逻辑层面）

**① 数据层是"单点故障"结构（最严重）**

全部数据存在 WebView 的 localStorage 里。localStorage 在以下场景全部丢失：卸载应用、系统设置里"清除存储"、部分国产 ROM 的"深度清理"、换手机。而唯一的容灾手段（导出/导入）在壳里是坏的（见 P0-1/2）。**当前版本的数据可靠性 = 0。**

**② 模块是"数据孤岛"，没有联动**

8 个模块共用一个 Store 却互不理睬，错失了"工作台"最大的价值——联动：

| 自然联动需求 | 现状 |
|---|---|
| 购物清单点"已买"→ 一键转为记账支出 | 无，要买完再手动记一笔 |
| 跑步消耗 → 计入健身热量缺口的"消耗侧" | 无，热量缺口只算了摄入 |
| 日程"健身房训练"完成 → 联动习惯/健身 | 无 |
| 今日页的"生活指数"汇总各模块 | 有，但算法失真（见 P1-4） |

**③ "生活指数"算法形同虚设**

日程项的计分逻辑是：有待办 +25 分，没有待办也 +25 分（注释写着 "all undone = still full potential"）。也就是说**逾期 10 件事和全部做完得分完全一样**。指数永远虚高在 60~90 分区间，失去激励意义。评分维度应该是"完成率"而不是"存在性"。

**④ 全量 innerHTML 重绘**

任何操作（哪怕只是习惯 +1 杯）都会 `App.render()` 重绘全部 8 个模块。数据量小无感，但一年后（数百条账目/跑步记录）每次点击都全量拼字符串重绘，会有可感知卡顿，且移动端耗电。建议后期按 tab 懒渲染 + 仅重绘当前模块。

**⑤ 壳层能力单薄**

`MainActivity` 只做了：加载 asset、开 JS/localStorage、返回键回退。缺：下载监听、文件选择、通知、分享接收、返回键退到首页确认退出（目前在任意 tab 按返回键直接退出或回退网页历史，体验不统一）。

## 三、Bug 清单（按严重度分级）

### P0 — 功能失效级（必须修）

| # | Bug | 位置 | 现象 | 修复方案 |
|---|---|---|---|---|
| P0-1 | **导出备份/导出 CSV 在 APK 内无效** | WebView 壳 | 点击"导出备份""导出CSV"无任何反应。Blob + `a.download` 在默认 WebView 里不触发下载 | 壳里加 `webView.setDownloadListener`，把 blob/data URL 转成字节流写入 `Download/` 目录；或在 JS 侧加兜底：`AndroidBridge.saveFile(base64)` JS 接口 |
| P0-2 | **导入恢复在 APK 内无效** | WebView 壳 | 点击"导入恢复"，文件选择器不弹出。`<input type="file">` 需要 `WebChromeClient.onShowFileChooser` 才会工作 | 壳里实现 `onShowFileChooser` + `onActivityResult` 回传文件 URI |
| P0-3 | **减重目标进度恒为 0%** | `Fitness.render` 目标进度计算 | 公式 `total/(-target)`：start=72.5、当前=71.5、目标=68 时，progress = -1/4.5 = **-22% → 被 clamp 成 0%**。减了 1kg 也显示 0%，永远不动 | 改为 `(start - last) / (start - targetWeight)`，增重目标用反向公式，注意除零 |

### P1 — 逻辑/体验级（强烈建议修）

| # | Bug | 位置 | 现象 | 修复方案 |
|---|---|---|---|---|
| P1-1 | **习惯连续天数每天早上"清零"** | `Data.habits.streak` | streak 从"今天"开始往回数，今天还没打卡 streak 就显示 0，火焰徽章上午消失、打卡后才出现 | 今天无记录时从昨天开始起算：`if(!todayLog) d = addDays(d,-1)` 再进循环 |
| P1-2 | **习惯无法补卡** | Habits 模块 | 所有打卡入口都写死 `todayStr()`，昨天忘打卡永远补不上，热力图只能看不能点 | 热力图格子加点击事件：点某天弹出录入该天的值 |
| P1-3 | **生活指数-日程项恒满分** | `Today.lifeIndex` | 有无待办/逾期都 +25 | 改为 `25 × (已完成数/总数)`，逾期每项再扣分 |
| P1-4 | **收藏页统计条布局错位** | `Media.render` | 4 个类型 + 1 个均分 = 5 个格子塞进 `repeat(3,1fr)`，且 `grid-column: span 0` 是无效 CSS → 第二行留一个空洞 | 网格改 `repeat(5,1fr)`（窄屏 3+2 居中），或删掉 span 逻辑 |
| P1-5 | **配速预览只监听"时长"输入** | `Run.addRun` | 先填时长再改距离，预览配速不更新 | 距离输入框也加 `oninput="Run._previewPace()"` |
| P1-6 | **用户输入未转义直接拼 innerHTML** | 全局（备注/标题/短评等） | 备注里输入 `a<b`、`"onmouseover=` 等内容会破坏渲染甚至被注入 HTML | 加一个 `esc()` 转义函数（`&<>"'`），所有用户文本插值前过一遍 |
| P1-7 | **所有数据"只能增删不能改"** | 全部模块 | 记错一笔账只能删掉重记；日程改时间要删了重建；习惯不能改名 | 每条记录加"编辑"入口，复用添加表单回填数据（数据结构已有 `update()`，只缺 UI） |
| P1-8 | **新用户第一天就被催备份** | `checkBackupReminder` | 阈值 20 条，而演示数据本身就 50+ 条 → 首次打开就弹"建议备份"横幅 | 阈值提到 100，且只统计非演示数据；或首次启动 7 天内不提醒 |
| P1-9 | **Demo.migrate 会无提示清掉老用户真实数据** | `Demo.migrate` | v1 用户若已录入真实数据，升级后被直接重置 | 迁移只删"未被用户修改过的演示条目"，或弹确认框 |
| P1-10 | **今日页"今日日程"数字歧义** | `Today.render` | 只统计未完成数：完成全部后显示"今日日程 0"，和"本来就没日程"无法区分 | 显示 `已完成/总数`，如 `3/5` |
| P1-11 | **热量记录静默截断** | `Data.fitness.addCal` | `slice(0,60)` 只留 60 条，超过悄悄丢弃旧数据 | 至少提示；或不设上限（数据量很小） |

### P2 — 细节打磨级

- Toast 在**顶部**弹出，Android 大众习惯在**底部**（且顶部会挡住 tab 栏）。
- Confirm 弹窗点遮罩不关闭（modal 可以），行为不一致。
- 弹窗打开时背景页面仍可滚动，无滚动锁定。
- tab 栏 8 个在窄屏溢出，**无"还有更多"的渐隐提示**，且切换后不会自动把激活 tab 滚到可视区。
- 跨午夜/跨月后日期、问候语、月份筛选不刷新（WebView 长驻后台的常见边缘场景）。
- 跑步时长 `Math.round(dur)` 强制整数分钟，30.5 分钟变 31。
- CSV 导出只替换了备注里的英文逗号，换行符会炸行。
- 账目金额显示 `¥8.5` 而非 `¥8.50`，统计又一律 `toFixed(0)`，精度风格不统一；建议数字统一 `font-variant-numeric: tabular-nums` 对齐。
- 导入 JSON 无 schema 校验，坏文件可能把 `budget` 导成字符串导致预算条 NaN%。
- PWA 相关代码（manifest.json、sw.js、安装按钮）在 APK 里是死代码——assets 里根本没有这两个文件，`beforeinstallprompt` 在 WebView 里永远不触发。要么补齐，要么删掉。
- 已完成日程（过去日期）直接从列表消失，没有"已完成"归档视图，成就感流失。

## 四、大众审美与交互审查

### 做得好的

- 设计 token 完整（zinc 灰阶 + indigo 主色 + 语义色），卡片、圆角、阴影体系统一，**整体观感干净克制，优于多数个人作品**。
- 空状态、Toast、确认弹窗、底部抽屉式 Modal（移动端）/ 居中 Modal（宽屏）都有，组件意识好。
- 书影音封面墙用标题 hash 生成渐变——思路聪明。
- 图表纯手写 SVG 零依赖，APK 只有 58KB，启动快、完全离线、无广告无追踪——**这本身就是对大众有吸引力的卖点**。

### 需要改进的（按大众审美习惯）

1. **导航位置反人体工学（最重要）**。8 个 tab 放在顶部，拇指够不着，且 Android 大众应用（微信/支付宝/抖音/Keep）全是**底部导航**。建议改底部 TabBar，并收敛为 5 个：`今日 / 记录（记账+清单）/ 习惯 / 健康（健身+跑步）/ 收藏`，或保留 8 个但底部可滑动。
2. **品牌色缺失**。主按钮、激活 tab 用的是纯黑（`var(--text)`），而品牌主色 indigo 只出现在 logo 和少量点缀上——黑药丸 + 紫 logo 视觉跳戏，大众会感知为"没有主题色"。建议主按钮/激活态统一用 indigo。
3. **无深色模式**。记账、打卡的高频场景是睡前，一片白底 + `maximum-scale=1.0` 在夜间体验差，且 OLED 屏耗电。主流生活类 App（时光序/滴答/钱迹/小日常）全部支持深色。CSS 变量体系已经搭好，加一套 `[data-theme=dark]` 变量 + 跟随系统即可，成本很低。
4. **封面渐变不可控**。hash 到 0~360 全色域，会随机出现脏色（土黄、灰绿），一面墙放一起审美波动大。建议预置 8~10 组精选高级感渐变（如山葵绿、薄雾紫、落日橙），按 hash 取模选取——可控且更耐看。
5. **启动白屏**。WebView 冷启动到 HTML 渲染之间有 0.3~1s 白屏。壳里把 `setBackgroundColor` 设为 `#FAFAFA`（已做一半），再加一张居中的启动 logo 图做 splash，廉价但立竿见影。
6. **数字排版**。统计大数字建议等宽数字（`tabular-nums`），金额统一两位小数；`¥` 符号用稍小字号跟在数字前，层级更专业（钱迹、一木都是这么做的）。
7. **图标语义**。"清单"tab 用购物车图标（实为待买清单，OK），但"收藏"实为书影音——图标是书，OK；整体没有歧义，只是 tab 太多时认读成本上升，回到第 1 条：收敛数量。

## 五、功能完整性逐模块审查

| 模块 | 现状 | 主要缺口 |
|---|---|---|
| 今日 | 问候+指数+待办聚合，结构好 | 指数算法失真；无个性化（昵称、背景） |
| 记账 | 记一笔/预算/月对比柱状图/消费结构饼图/CSV | **无编辑、无搜索、无账户概念、无周期账（房租/订阅）、分类不可自定义、预算只有总预算没有分类预算** |
| 习惯 | 三种打卡类型、连续天数、30 天热力图 | **无法补卡、只有"每天"一种频率（不能每周 3 次）、无提醒** |
| 健身 | 体重/体脂/BMI/目标进度/热量缺口/周计划 | 目标进度 bug；热量只能靠手输数字（坚持率极低）；无运动消耗侧 |
| 跑步 | 手动记录/PB/8 周跑量/跑鞋寿命 | 手输定位要明确是"跑步日记"；无月/年统计页 |
| 日程 | 分组（逾期/今天/本周/更远）、分类 | **无提醒通知、无重复规则、无月历视图、无编辑** |
| 清单 | 优先级/预估价 | 不能转记账；无数量字段 |
| 收藏 | 书影音四类型、评分、封面墙/列表 | 无条目库（手输标题）；无阅读进度/观看进度 |

## 六、与市面成功产品对比

| 维度 | 生活工作台 | 时光序（最像的对标） | 滴答清单 | 钱迹 | 小日常 | Keep/薄荷 | 豆瓣 |
|---|---|---|---|---|---|---|---|
| 定位 | 离线个人生活记录 | All-in-one 生活管理 | 任务/日程 | 专业记账 | 习惯打卡 | 垂直健康 | 书影音档案 |
| 功能广度 | 8 模块 | 18+ 功能 | 中 | 窄而深 | 窄而深 | 窄而深 | 窄而深 |
| 单功能深度 | ★★ | ★★★ | ★★★★★ | ★★★★★ | ★★★★ | ★★★★★ | ★★★★★ |
| 提醒通知 | ✗ | ✓ | ✓ | ✓ | ✓ | ✓ | ✓ |
| 云同步/多端 | ✗ | ✓ | ✓ | ✓ | ✓ | ✓ | ✓ |
| 桌面小组件 | ✗ | ✓ | ✓ | ✓ | ✓ | ✓ | ✗ |
| 深色模式 | ✗ | ✓ | ✓ | ✓ | ✓ | ✓ | ✓ |
| 数据可导出 | ✗（当前壳内失效） | ✓ | ✓ | ✓ | ✓ | ✓ | ✓ |
| 离线/隐私/无广告 | ✓✓✓ | 含广告+VIP | 部分付费 | 口碑极好 | 轻量 | 重广告 | 重运营 |

**对比结论：**

1. **正面拼深度没有胜算。** 记账拼不过钱迹（3 秒快记、自动记账、资产管理），日程拼不过滴答（提醒、重复、日历视图），习惯拼不过小日常（频率、提醒、周报）。
2. **你的差异化恰恰在"反面"**：58KB、零权限、零广告、零账号、完全离线、数据全在自己手里。市场上"All-in-one 且纯离线无广告"的生态位几乎是空的——时光序功能全但广告和 VIP 墙劝退了大量用户。
3. **但"离线"定位成立的前提是数据绝对安全**——当前导出/导入双坏，恰好砸掉了自己唯一的立足点。修好 P0 之前，定位故事讲不圆。
4. 值得抄的作业：
   - **时光序**：模块可开关/排序（用户只要 3 个模块就隐藏其余 5 个）；
   - **钱迹**：记账主界面就是数字键盘，一步完成；分类可自定义；
   - **小日常**：打卡有震动/音效反馈 + 补卡机制，激励闭环完整；
   - **滴答**：日程的重复规则和本地通知是留存核心。

## 七、修改方案（按优先级三阶段）

### 阶段一：止血（1~2 天，不做不能发布）

1. **壳层补两个桥**（或直接用支持导出的打包方案重新出包）：
   - `setDownloadListener` → 写文件到 `Download/生活工作台/`，JS 侧对 blob 转 base64 走 `JavascriptInterface`；
   - `WebChromeClient.onShowFileChooser` → 系统文件选择器；
   - 顺手补：双击返回键才退出、启动 splash、`usesCleartextTraffic` 关掉。
2. 修 `Fitness` 目标进度公式：`(起始-当前)/(起始-目标)`。
3. 修 `streak` 今晨清零：今天未打卡时从昨天起算。
4. 全局加 `esc()` 转义，所有用户输入插值前调用。
5. 备份提醒阈值 20 → 100，且首装 7 天内不弹。

### 阶段二：补齐体验短板（1 周）

6. **统一编辑能力**：所有记录加"编辑"（复用添加弹窗回填 + 已有的 `update()` 方法）。
7. **习惯补卡**：热力图格子可点击，录入任意历史日期。
8. **导航改版**：顶部 tab → 底部 TabBar，收敛为 5 个一级入口（健康合并健身+跑步，记录合并记账+清单）。
9. **深色模式**：`prefers-color-scheme` + 手动开关，CSS 变量直接换一套。
10. **生活指数改算法**：各项按"完成率"计分，逾期扣分，让分数有波动、有激励。
11. 修复 P1-4/5/8/9/10 及 P2 细节清单。
12. 封面渐变改为预置色板取模。

### 阶段三：建立竞争力（2~4 周）

13. **本地通知**（壳层桥接 `AlarmManager` + `NotificationCompat`）：日程提醒、习惯晚间未打卡提醒——这是留存的命门，也是与竞品"能用"和"不能用"的分水岭。
14. **模块联动**：购物"已买"→ 弹"顺手记一笔？"（预填名称/价格）；跑步消耗计入健身热量页。
15. **桌面小组件**（`AppWidgetProvider`）：今日待办 + 习惯一键打卡——安卓生活类 App 的留存利器，且和你"轻量"定位契合。
16. **模块开关**：设置里可隐藏不用的 tab，"我的工作台我做主"。
17. 记账增强：编辑/搜索/自定义分类/周期账（房租、订阅自动入账）。
18. 日程增强：重复规则（每周/每月）、月历视图。
19. 数据保险箱：自动每周本地快照（保留最近 4 份在应用私有目录），导出备份可选加密。
20. 长期可选：WebDAV/私有云同步——守住"数据归用户"定位的同时解决多端问题，和竞品的账号体系形成差异。

## 八、一句话总结

**底子是好底子：设计系统完整、代码有容错意识、细节有洞察。但请先修好"数据出不去"这个死穴（P0-1/2/3），再把导航和深色模式补齐——做到这两点，它就能从"每个功能的简配版"变成"市场上稀缺的纯离线无广告 All-in-one 生活台"，这个生态位是真实存在的。**
